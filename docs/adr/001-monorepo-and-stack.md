# ADR-001: Monorepo Structure and Core Stack

**Status:** Accepted  
**Date:** 2026-07-31  
**Author:** Architect

---

## Decision

Turborepo + pnpm workspaces monorepo with three packages: `api/`, `ui/`, `packages/types/`.

## Stack

| Concern | Choice | Reason |
|---------|--------|--------|
| Monorepo | Turborepo + pnpm | Best build caching, parallel task execution |
| API runtime | Bun | Fastest JS runtime; built-in test, bundler, env |
| API framework | Hono | Edge-native, Bun-native, minimal overhead |
| UI framework | Next.js 15 (App Router) | RSC, PPR, best SEO story |
| DB | Neon Postgres + Drizzle | Serverless, free tier, SQL-first ORM |
| Lint/Format | Biome | Replaces ESLint + Prettier; one config, 50x faster |
| Auth | Clerk | Webhook → sync to DB; zero auth code to write |
| Shared types | Zod in `packages/types/` | Single schema source; both API + UI import from here |

## Rules (enforced in CI)

1. `packages/types/` is read-only for devs — only Architect modifies schemas
2. No `any` types — `strict: true` in all tsconfigs
3. All routes must use Zod middleware validation
4. No direct `fetch()` in UI — use hooks from `lib/hooks/`
5. Every service function has a Vitest unit test

## Consequences

- Turborepo caches build artifacts — subsequent builds near-instant
- Single `pnpm install` at root installs everything
- Type changes in `packages/types/` immediately reflect in both api/ and ui/ (workspace protocol)
- Biome single config at root applies to all packages
